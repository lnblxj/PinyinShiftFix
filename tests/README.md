# Test tools

These are development diagnostics, not background components of the fix. Historical reports and personal logs are intentionally excluded.

## Build

From the repository root, run `tests\build.cmd`. Both executables are written to `bin/`. Ready-to-run copies are included in tests/prebuilt/ in this developer archive. The end-user Release does not include diagnostics.

## EngineTests.exe

Offline tests of the production patch engine. Requires two original samples and their matching PDBs:

```powershell
.\EngineTests.exe C:\samples\2913 C:\samples\6456
```

Each directory must contain `InputService.dll` and `InputService.pdb`. Identities are in `data/known-builds.json` in this developer package. Microsoft files are not bundled.

The test reads samples without installing or patching the system. It verifies both known builds, symbol recognition, expected hashes, and rejection cases. Exit code 0 means all assertions passed; a nonzero exit code indicates failure. A new build needs the analyzer below rather than replacing these fixed regression fixtures.

## TriggerLab.exe

A visible foreground-only input reproduction harness. Select modern Microsoft Pinyin, finish ongoing composition, then run:

```powershell
.\TriggerLab.exe C:\analysis\input-result.txt
```

Create the output parent directory first. The harness focuses its own window, runs scenarios, writes the requested log, and exits. Do not switch windows during the test. Key injection stops if another process becomes foreground.

It temporarily changes the test window's IME mode and legacy hotkey 0x11. Normal exit restores the hotkey; forced termination may skip cleanup. Only run in a user-authorized test session.

The output is a diagnostic log, not an automated pass/fail verdict. Verify the committed uppercase result is ASCII R, normal Chinese commitment is correct, English commitment is abc123, and Chinese punctuation remains correct. Record the system DLL hash alongside the results. The labels original/restored describe hotkey phases, not the system file's patch state.

## Python analysis and disassembly

Scripts are in the developer package root tools/ directory. Run the following commands from the package root. They require a separately installed Python 3 environment:

```powershell
python -m pip install -r tools/requirements.txt
python tools/analyze_sample.py C:\samples\InputService.dll --pdb C:\samples\InputService.pdb --out C:\analysis\new-result
```

The output directory must not exist. Use `--download-symbols` instead of `--pdb` to request the matching Microsoft symbols. `--emit-patched-copy` optionally creates a patched copy in the output directory, never in the system directory.

For disassembly, install `tools/requirements-disassembly.txt` and run `tools/disassemble.py --help`. It uses `symbols.json` generated by the analyzer and an explicit executable RVA. It prints instructions without writing files.

Keep generated logs and reports local or redact them before sharing. They may contain local sample paths. See the source archive's English `docs/AGENT_GUIDE.md` for adaptation methodology and evidence requirements.
